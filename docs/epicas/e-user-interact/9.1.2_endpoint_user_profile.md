# 9.1.2 — Endpoint para obtener perfil de usuario

## Objetivo

Implementar un endpoint que permita obtener el perfil de un usuario dado su `username`, respetando el modelo definido en 9.1.1.  
El endpoint requiere autenticación.

---

## Ruta

`GET /api/users/:username`
- Autenticación obligatoria.
- `username` es único.
- Internamente se resuelve a `user_id`.
    

---

## Comportamiento

1. Verificar que el usuario está autenticado.
    - Si no → `401 Unauthorized`.
        
2. Buscar el usuario objetivo en base de datos mediante `username`.
    - Si no existe → `404 Not Found`.
        
3. Construir la respuesta del perfil según el modelo definido en 9.1.1:
    - Siempre devolver los campos públicos.
        
    - Los campos adicionales (`posts`, `friend_list`, `online_status`) dependerán de la lógica de visibilidad (9.1.3).
        

---

## Respuesta base (usuario autenticado, no amigo)

{  
  "user_id": "uuid",  
  "username": "string",  
  "avatar_url": "string|null",  
  "bio": "string|null",  
  "friendship_status": "none|pending|accepted|rejected"  
}

---

## Respuesta ampliada (amigo o propietario)

{  
  "user_id": "uuid",  
  "username": "string",  
  "avatar_url": "string|null",  
  "bio": "string|null",  
  "friendship_status": "accepted",  
  "online_status": true,  
  "posts": [],  
  "friend_list": []  
}

---

## Códigos de estado

- `200 OK` → Perfil encontrado.
- `401 Unauthorized` → Usuario no autenticado.
- `404 Not Found` → Usuario inexistente.
- `400 Bad Request` → Parámetro inválido.

---

## Notas Generales

- `friendship_status` es relativo al usuario autenticado que realiza la consulta.
- `user_id` se expone únicamente como identificador interno en la API y no se muestra en la interfaz de usuario.
- La lógica detallada de visibilidad se implementará en 9.1.3.
